# easyCode - プログラミング学習支援アプリケーション

easyCodeは、プログラミング初学者がAIと共に学習を進めることができるWebアプリケーションです。

## モード

4つのモードは、画面上端の番号つきレーン（01〜04）で切り替えます。

| モード | ファイル | 内容 |
| --- | --- | --- |
| 01 実験（既定） | `index.html` | ブロックとPythonコードを相互変換しながら学ぶ4分割画面 |
| 02 レッスン | `lessons.html` | 入門・基礎練習・共通テスト対策・二次試験対策・模試 |
| 03 スケッチ | `drawing.html` | p5.js風のAPIでグラフィックを描く（ブロック・フローチャート対応） |
| 04 早見表 | `python-guide.html` | Pythonの文法と共通テスト用プログラム表記のリファレンス |

## 主な機能

### 1. 01 実験（トップページ）

画面は4つに分かれています。

- **左上: Pythonコード** — 直接編集できるコードエディタ
- **右上: フローチャート** — 今のコードの流れを図で表示
- **左下: ブロックエディタ** — ブロックでプログラムを組み立てます（Blockly / geras レンダラー）
- **右下: 実行結果** — Pyodideによる実行と、1行ずつたどれるステップ実行

主な特徴:

- **ブロック ⇄ コードの相互変換**: ブロックを動かすとコードが変わり、コードを書き換えるとブロックが組み直されます。ブロックにできない書き方は「Python」ブロックとしてそのまま保持されるので、どんなコードでも往復できます。
- **フローチャート自動生成**: 常に「今のPythonコード」から描くので、ブロックでも手書きでも同じように表示されます。教科書どおりの記号（端子＝角丸、処理＝長方形、判断＝ひし形、入出力＝平行四辺形、合流＝小さい丸）で、`for` は「初期化 → 判断 → 本体 → 更新 → 判断にもどる」に分解して描きます。
- **やさしい日本語のラベル**: `print(i)` は「i を表示する」、`i % 15 == 0` は「i は 15 で割り切れる？」のように言いかえて表示します。パネルの「やさしい日本語 / コードのまま」で切り替えられます。
- **終わらないコードでも固まらない**: `while True:` のようなコードは、実行もステップ実行も自動で打ち切って、やさしいメッセージを出します。
- **ステップ実行（Python Tutor風）**: `sys.settrace` で実行の記録を取り、前後に自由にたどれます。実行中は画面が2つに分かれ、左側で「コード / フローチャート / ブロック」を切り替えられます。変数は**型（リスト・辞書・整数…）と中身の要素**まで表示し、変わった値とその行で使われている変数を強調します。
- **画面の分け方を選べる**: ツールバーで **4面 / 3面 / 2面** を切り替えられます。
  - 4画面 … コード・フローチャート・ブロック・実行結果をすべて表示
  - 3画面 … コード（縦長）・フローチャート・実行結果（ブロックは隠す）
  - 2画面 … 左はタブで「コード / フローチャート / ブロック」を切り替え、右は実行結果
  ステップ実行を始めると自動で2画面になり、終わると元の分け方にもどります。
- **各パネルの拡大**: パネル右上の拡大ボタンで全画面表示（Escで戻る）。
- **共有リンク**: 「共有」で、今のコードが入ったリンクを作れます。コードは圧縮して URL に入るので、サーバーに保存せずに渡せます。
- **先に予想（じっくりモード）**: 実行の前に出力を予想して書きます。補完もひかえめになります（後述）。

### 2. 02 レッスン（AIなしで答え合わせまでできます）

5 つのコースがあります。左の一覧から、どの問題でも自由に選べます。

| コース | 中身 |
| --- | --- |
| 入門 | はじめての人向け。10 課 30 ステップ。読む → 少し考える → 自分で書く |
| 基礎練習 | 既存の 20 問。入門で覚えたことの練習 |
| 共通テスト対策 | 19 問。共通テスト用プログラム表記で読む・埋める |
| 二次試験対策 | 12 問。自分で書いて、複数のテストで自動採点 |
| 模試 | 3 セット × 5 問（各 100 点）。制限時間なし。成績はこの端末に残ります |

**出題の形は 4 つ**

- **読む**（入門）… 説明を読み、見本を動かしてみる。答え合わせはありません
- **追う**（トレース）… プログラムを読んで、表示される値や変数の最終値を答えます。
  **答えるまで実行できません**。先に予想してから確かめる進め方です
- **埋める**（穴埋め）… 【ア】【イ】に入るものを選びます。埋めたプログラムをその場で実行できます
- **書く**（記述）… 自分で書き、いくつかの入力で一括採点します。
  入力・期待・実際・判定を並べた表が出るので、どこがちがうか分かります

**答え合わせはすべてローカルで行います**（APIキーは不要）。
行末の空白・改行コード・末尾の空行のちがいは同じとみなすので、
合っているのに不正解と言われることがありません。

### 2-1. 共通テスト用プログラム表記

学習者は **Python で書き**、アプリが自動で
[共通テスト用プログラム表記](https://www.dnc.ac.jp/)（大学入試センターが公表している疑似言語）に
直して見せます。「共通テスト表記」タブを開くと、試験と同じ見た目で読めます。

| Python | 共通テスト用プログラム表記 |
| --- | --- |
| `print("こんにちは")` | `表示する("こんにちは")` |
| `x = int(input())` | `x = 【外部からの入力】` |
| `len(Data)` | `要素数(Data)` |
| `a // b` | `a ÷ b` |
| `if x < 3:` | `もし x < 3 ならば:` |
| `elif` / `else:` | `そうでなくもし … ならば:` / `そうでなければ:` |
| `while n < 10:` | `n < 10 の間繰り返す:` |
| `for x in range(0, 10):` | `x を 0 から 9 まで 1 ずつ増やしながら繰り返す:` |
| `Hyo[1][2]` | `Hyo[1,2]` |
| 字下げ | `│` と `└` でブロックの範囲を示す |

- **行番号が 1 対 1 で対応します**。ステップ実行で光る行が、表記側でも同じ行になります
- 添字は 0 から、配列名は先頭大文字、繰り返しの「〜まで」はその値を含む、
  `表示する()` はカンマの間に空白が入る——この 4 点は問題文にも出します
- 表記に無い書き方（`def` や `for x in リスト` など）は直さず、そのまま残して知らせます
- 01 実験と 03 スケッチでも、フローチャートの横のボタンから同じ表記が見られます

### 2-2. 進み具合

- 解けた問題には が付き、コースごとに「7/30」のように数が出ます
- 書きかけのコードは問題ごとに残るので、他の問題を見てから戻れます
- 模試の最高点が一覧に出ます。「設定」から消せます

### 3. 03 スケッチ

- **左側はタブで切り替え**： コード / ブロック / フローチャート / サンプル
- **右側はキャンバスと実行結果**。`setup()` と `draw()` を書くとアニメーションになります
- **ブロックで描ける**：円・四角・色・回転などが専用ブロックになっていて、コードと相互変換されます
- **サンプルは説明つき**：引数の意味を書いてあり、押すとコードに追加されます
- **書き方は p5.js のリファレンスと同じ**：`circle(200, 200, 100)` のように前置きなしで書けます。
  `strokeWeight(4)` のような英語のつづりも、`stroke_weight(4)` のような Python らしいつづりも、
  これまでの `p5.circle(...)` も、すべて同じ命令として動き、同じブロックになります
- `abs` `round` `min` `max` `pow` は Python にもとからあるものをそのまま使います
  （`abs(-5)` が `5.0` ではなく `5` になります）
- 塗りや線の既定値は p5.js に合わせてあります（塗り＝白、線＝黒、太さ1、線の端＝丸）
- `draw()` のたびに座標系をもどすので、`rotate()` の書き忘れで絵がずれ続けることがありません（p5.js と同じ動き）
- **1 秒あたりのコマ数も p5.js と同じ 60 が既定**です。`frameRate(30)` で変えられ、
  `frameRate()` は今出ているコマ数を返します
- `createCanvas(400, 300)` でキャンバスの大きさを決められます（Processing のつづり `size(...)` も同じ）。
  そのあと `width` と `height` が使えます
- `mouseX` `mouseY` `mouseIsPressed` `key` `keyIsPressed` は、`draw()` の中でその時の値になります
- `noLoop()` で `draw()` を止め、`loop()` で動かし直せます（`isLooping()` で今の状態が分かります）
- **外で作った変数を `draw()` の中から書きかえられます**（p5.js の `let x = 0;` と同じ感覚）。

  ```python
  x = 0
  d = 1

  def setup():
      createCanvas(400, 400)

  def draw():
      background(220)
      circle(x, 200, 50)
      x = x + d * 5      # global と書かなくてよい
      if x > 400:
          d = -1
      if x < 0:
          d = 1
  ```

  Python のきまりでは `UnboundLocalError` になる書き方ですが、03 スケッチでは
  「外で値を入れてある名前を関数の中で書きかえているとき」だけ `global` を自動で足しています。
  引数と同じ名前や、関数の中だけで作った名前は、これまでどおり関数の中だけのものです。
  この置きかえは 03 スケッチだけで、01 実験と 02 レッスンは Python のきまりのままです
- 描画関数・数学関数・色の関数など **113 項目を実機で検証済み**（`rotate` `translate` `scale` `angle_mode` `erase` なども含む）

### 4. 先に予想（考える時間をつくる）

補完がすぐ答えを出してしまうと、考える時間がなくなります。ツールバーの「先に予想」を入れると：

- 補完は自動で出さず、<kbd>Ctrl</kbd>+<kbd>Space</kbd> を押したときだけ出ます（AIの先読みも止まります）
- 実行の前に「出力はどうなると思う？」と**予想を書く欄**が出ます
- 実行後、**予想と実際を見くらべて**、ちがっていればステップ実行をすすめます

予想してから実行する進め方は、プログラミング教育で使われている
[PRIMM](https://teachcomputing.org/blog/using-primm-to-structure-programming-lessons/)（Predict → Run → Investigate → Modify → Make）にもとづいています。

### 5. コード補完・整形（APIキー不要）

すべてのモードで使えます。**AIやAPIキーが無くても動きます。**

- **コード補完**: 書いているコードを解析して、自分で作った変数・関数・クラス、import したモジュールの中身、変数の型から分かるメソッド（文字列なら `.upper()` など）、組み込み関数、よく使う書き方のひな形を候補に出します。`Ctrl+Space` で候補一覧、`Tab` で確定。03 スケッチでは `p5.` の API も候補に出ます。
- **字下げ**: 崩れた字下げやタブ混在を直します。字下げがまったく無いコードを貼り付けても、`:` と `else` / `elif` の対応から正しい形に組み直します。
- **整形**: 字下げに加えて、記号まわりの空白（`x=1` → `x = 1`）、カンマの後の空白、コメントの体裁、空行の数を整えます。
- どちらも次のことを守ります。
  - **文字列（`"""..."""` を含む）とコメントの中身は1文字も変えない**
  - **括弧で複数行にまたがる文は、書いた人のそろえ方を保つ**（閉じ括弧は文の先頭にそろえる）
  - **深くなれるのは「`:` で終わる行の次」だけ**（Python と同じ規則）
  - `else` は Python と同じく**同じ列にある見出しと組にする**（`for ... else` が内側の `if` に付かない）
  - 何度かけても結果が変わらない
- **インデントガイド**: エディタに字下げの目安になる縦線を表示します。

APIキーを設定すると、上記に加えて「行の続きの提案」がAIから薄い文字で出ます（無くても補完は動きます）。

### 6. AIサポート機能（APIキーが必要）

- **問題解説生成**: 現在の問題について簡潔な解説を生成
- **コードレビュー**: 書いたコードに対して良い点と改善点をフィードバック
- **AIチャット**: プログラミングに関する質問に短く的確に回答
- **問題生成**: AIが新しい練習問題を自動生成

APIキーが無いときは、**AIらしい作り話を返さず**「キーが必要です」とだけ伝えます。
実行・ブロック・フローチャート・コード補完・整形は、キーが無くてもすべて使えます。

### 7. インタラクティブな実行環境

- `input()`を使用したコードでは、実行時に入力フォームが表示されます。
  `input("名前は？")` の**問いかけが実行結果と入力欄の両方に出る**ので、何を聞かれているのか分かります
- ステップ実行では、使う入力値を先にまとめて指定

### 8. エラーの見せかた

学習者がつまずくのはたいていエラーの読み方です。Traceback をそのまま出すのではなく、
**何行目で・どのコードで・どういう意味か**を日本語で見せます。

```
 3 行目でエラーが起きました
   print(kazu)
NameError: name 'kazu' is not defined
 「kazu」という名前は、まだ作られていません。打ちまちがいがないか、
   使う前に代入しているかを見てみましょう。
```

- 行番号は**学習者が書いた行そのもの**です（内部で足しているコードの分がずれません）
- `NameError` `SyntaxError` `IndentationError` `TypeError` `ZeroDivisionError` `IndexError`
  `KeyError` `ValueError` `AttributeError` などに日本語のヒントが付きます。
  同じ `TypeError` でも「引数の数が足りない」「文字列と数値をつないだ」で説明を変えます
- `while True:` のような終わらないコードは **10 秒で打ち切って**その旨を伝えます
  （すべてのモードに入っています）

## 使い方

1. **APIキーの設定**（AI機能を使う場合）
 - サイドバー上部の「Gemini APIキーを取得する →」リンクをクリック
   - Google AI StudioでAPIキーを取得し、入力して保存

2. **ブロックで組み立てる**
   - 左下のブロックエディタからブロックをドラッグ
   - 左上にPythonコード、右上にフローチャートが自動で表示されます

3. **コードで書く**
   - 左上のエディタに直接入力すると、ブロックが組み直されます
 - ブロックが不要なら「ブロックを閉じる」

4. **動きを確かめる**
   - 「実行」で動かす
   - 「ステップ実行」で1行ずつたどる（← → キーでも移動できます）

5. **書きやすくする**
   - `Ctrl+Space` でコード補完（APIキー不要）
 - 「字下げ」で字下げを直し、「整形」で全体を整えます

## 似たツールとの違い

同じ領域には、大きく3種類のツールがあります。

| 種類 | 例 | できること | していないこと |
| --- | --- | --- | --- |
| ブロック ⇄ テキスト | [EduBlocks](https://www.computingatschool.org.uk/resources/2025/november/edublocks-from-blocks-to-text/)、[Pencil Code (Droplet)](https://arxiv.org/pdf/1705.09413)、Code.org App Lab | ブロックとコードを行き来しながら文法を学べる | フローチャートは無い／実行の途中を追えない |
| フローチャート中心 | [RAPTOR](https://raptor.martincarlisle.com/)、Flowgorithm、Visual Logic | 図でアルゴリズムを組み、図の上で実行を追える | ブロックは無い／Python を自分で書く体験にはつながりにくい |
| 実行の可視化 | Python Tutor | 1行ずつ変数の変化を追える | ブロックもフローチャートも無い |

複数の表現を並べる研究では、**フローチャートとコードを同時に見せると初学者の理解を助ける**一方、その対応づけは**片方向にとどまることが多い**と報告されています
（[Flowchart-Based Programming Environments: A Survey](https://www.researchgate.net/publication/268514075_Flowchart-Based_Programming_Environments_for_Improving_Comprehension_and_Problem-Solving_Skill_of_Novice_Programmers_A_Survey)、
[From Code to Concept: Evaluating Multiple Coordinated Views in Introductory Programming](https://arxiv.org/pdf/2509.26466)）。

**easyCode の新しいところ**

1. **3つの表現が同時に、双方向でそろう** — ブロック・Pythonコード・フローチャートが常に同じプログラムを指します。ブロックを動かしてもコードを書いてもよく、どちらからでも往復できます（フローチャートは常にコードから描かれます）。
2. **ステップ実行が3つすべてを同時に光らせる** — 1行進めるたびに、コードの行・フローチャートの図形・ブロックが同時に強調されます。「今どこを動いているか」を、どの表現で見ていても見失いません。
3. **図のラベルがやさしい日本語** — フローチャートを「読める文章」にすることで、コードの意味と図の意味を結びつけられます。
4. **考える時間を守る設計** — 補完を弱めて予想を挟む「先に予想」を、環境そのものに組み込んでいます。
5. **サーバー不要** — すべてブラウザの中で動き、共有もリンクだけで完結します（コードは URL に圧縮して入ります）。

## 技術仕様

- **フロントエンド**: HTML, CSS, JavaScript (ES6 Modules)
- **Pythonランタイム**: Pyodide (ブラウザ内Python実行環境)
- **ブロックエディタ**: Blockly (geras レンダラー / 日本語ロケール)
- **フローチャート**: Mermaid
- **コードエディタ**: CodeMirror
- **AI**: Google Gemini API

### カスタマイズ

- 新しい問題を追加: `lessons/*.json` に足します。型は `read` / `trace` / `blank` / `code` の 4 つ。
  **`trace` の `answer`、`blank` の `expectedOutput`、`code` の `solution` は必ず入れてください**
  （`tests/browser.html` が実際に走らせて、答えが合っているか照らし合わせます）。
  乱数を使う問題は `prelude` で `random.seed(...)` を決めてください
- 基礎練習の問題を追加: `problems/` に JSON を足し、`lessons/basic.json` から `ref` で参照
- 見た目の変更: `css/theme.css` のデザイントークン（`:root`）を編集すると全ページに反映されます
- ブロックの追加: `module/blockdefs.js` の表に1行足すと、ブロックの見た目・Python生成・Python読み取りがまとめて作られます
- ブロックへの変換規則: `module/py2blocks.js`
- 補完候補の追加: `module/pycomplete.js` の辞書（`BUILTINS` / `TYPE_METHODS` / `MODULE_MEMBERS` / `SNIPPETS`）
- AI応答の調整: `module/ai.js`のプロンプトとmaxTokensを変更

### 検査（テスト）

ブラウザ無しで確かめられる部分と、実際に動かさないと確かめられない部分に分かれています。

```bash
node tests/run-node.mjs
```

`pyformat`（整形）・`humanize`（日本語への言いかえ）・`flowchart`（図の組み立て）・
`pycomplete`（補完）・`pyrun`（エラーの言いかえ）・`grade`（答え合わせ）・`ktph`（共通テスト表記への言いかえ）・`lessons-data`（レッスンのデータ）を、482 項目で確かめます。とくに整形については

- 整ったコードは**変わらない**
- 何度かけても**結果が同じ**
- **空白以外の中身は1文字も変わらない**
- 壊れた入力でも**例外を出さない**

という性質そのものを検査しています。

ブラウザが要るものは、サーバーを立てて `tests/browser.html` を開きます（712 項目）。

- **Python ⇄ ブロックの往復**：往復させたコードを実際に実行し、**出力が変わらない**ことを確かめます
- **ツールボックスの全ブロック**：1つずつ置いて、作られたコードが Python として読めることを確認
- **ステップ実行**：記録の中身（型・要素・行番号）と、エラーや文法エラーの伝え方
- **p5 ライブラリ**：127 項目。画素を読んで `rotate` `translate` `scale` `erase` が効いているかまで確認
- **書き方のちがい**：`circle(...)` `strokeWeight(...)` `stroke_weight(...)` `p5.circle(...)` がすべて動くこと
- **コードの実行とエラー**：エラーの種類と**行番号**が学習者のコードと合っていること
- **終わらないコード**：`while True:` が決めた時間で止まること
- **大きなコード**：600 行でもフローチャートが止まらないこと
- **共有リンク**：圧縮して復元できること（圧縮が使えないブラウザでも動くこと）
- **レッスンの中身**：すべての問題を実際に走らせて、書いてある答えと照らし合わせます。
  トレースの答え・穴埋めの出力・記述の解答例・模試の配点（各 100 点）・id の重なり・
  共通テスト対策の問題が表記に直せること・乱数の種が決まっていることまで見ます

### 画面まわりで確かめていること

自動検査に載せにくいところは、ブラウザを実際に操作して確認しています。
